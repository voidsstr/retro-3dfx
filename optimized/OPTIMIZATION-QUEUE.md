## Strategy
Ordering rationale: items 1-4 are one-line-to-tiny changes with byte-identical expected output — they establish trustworthy A/B baselines and shake out the build/deploy/bench loop cheaply. Items 5-7 are C-level state/redundancy eliminations in the 'state monster' and color path. Items 8-10 are the hot-loop restructures (vertex dedup is the single highest-confidence big win — the audit found indexed draws re-transform every shared vertex per reference with zero sharing). Item 12 (multitexture) has the largest ceiling but changes rendered output, so it must come last to keep pixel-diff A/B meaningful for everything before it.

Cross-cutting flags: (1) Q3 FPU control word — Q3 runs _controlfp(_PC_24) (24-bit precision, round-to-nearest). icd-qifist changes float->int from chop to nearest (only queue item with intentional numeric drift besides multitexture); all asm edits (glide-xdraw2-deadcode-stats, glide-mmx-fifo) must keep the x87 stack balanced and pair femms/emms, since CW/stack corruption under _PC_24 shows up as delayed geometry garbage. (2) Voodoo5 dual-VSA100 SLI — the SSTCP packet-3 stream is broadcast to both chips; glide-paramindex-gate and glide-mmx-fifo must preserve exact packet layout/ordering (a layout mismatch corrupts both chips identically; a width-only change like movq is safe). Pixel-diff harness should run at the SLI band boundaries' native resolution to catch per-band artifacts.

Not queued, deliberately: /QIfist for glide3x (its _ftol refs are all cold-path — ditex/distate/diget/gu/gpci — risk without reward); enabling __GL_CODEGEN or __GL_SST_GLIDE_VTX (both dead code paths of unknown quality, huge validation cost); __glXForm3_Batch revival (marginal after icd-vertex-dedup). Bench-order dependency: measure icd-color4ub-lut BEFORE icd-vertex-dedup — dedup shrinks the per-vertex multiplier that makes the LUT win visible, so the reverse order understates it. Expected compounding: items 1-11 realistically stack to ~20-40% before multitexture; multitexture is its own step-change on top.

## Full details per item

### 1. icd-flags-g6-ob2 (3dfxogl)
- **files:** /home/voidsstr/development/retro-3dfx/toolchain-3dfx/prefix/drive_c/3dfx/SWLIBS/OPENGL/GLIDE3X/INCLUDE/MAKE/OGL.MAK (line ~177, release CPP_OPTS)
- **change:** Change release codegen from /O2 /G5 to /O2 /G6 /Ob2 — P6 (PPro/PII/PIII) instruction scheduling instead of Pentium-classic, plus inline-any-suitable (VC6 /O2 only implies /Ob1). Single makefile edit; all five sub-libs (GLCORE, SST, WGL, MGL, TRACE) inherit it. Toolchain already verified to accept these flags with exit 0 and no D4002.
- **expected:** 1-3% FPS (better scheduling of the C portions of the T&L path; the x87 hand-asm is unaffected)  |  **risk:** Very low — pure scheduling/inlining, no semantic change. VC6 emits no CMOV/SSE regardless, so the binary still runs on any Pentium-class CPU.
- **verify:** Pixel diff on q3dm1 screenshot must be byte-identical (no math changes). Sanity: dumpbin the new DLL, confirm no illegal-instruction reports on the P3 box.

### 3. icd-qifist (3dfxogl)
- **files:** /home/voidsstr/development/retro-3dfx/toolchain-3dfx/prefix/drive_c/3dfx/SWLIBS/OPENGL/GLIDE3X/INCLUDE/MAKE/OGL.MAK (release CPP_OPTS)

### 5. glide-state-dedup (glide3x)
- **files:** /home/voidsstr/development/retro-3dfx/toolchain-3dfx/prefix/drive_c/3dfx/H5/GLIDE3/SRC/DISTATE.C (grAlphaBlendFunction ~386-409, grAlphaTestFunction ~453, grAlphaCombine ~498, grColorCombine, grTexCombine, grDepthBufferFunction, grChromakey*, grFogMode — every setter that stores args + INVALIDATE())
- **change:** Add early-out redundancy filtering to the glide state setters: compare incoming args against the shadowed current values in gc and return without INVALIDATE() when identical. Q3's shader system re-issues identical blend/combine/depth state per stage constantly; today every call dirties state and forces _grValidateState on the next draw. Implement as a small macro so each setter is a 2-line change and individually auditable.
- **expected:** 3-8% FPS (skips _grValidateState + the unconditional _grUpdateParamIndex cascade for the common redundant-set case)  |  **risk:** Medium — the shadow must never disagree with hardware. Force-invalidate on context create, grGlideSetState/grGlideGetState restore, grSstSelect, and any power-on/lostContext recovery, or a filtered 'redundant' set silently leaves stale hardware state. Audit each setter for side effects beyond the stored args before filtering it (some setters also touch other derived state).
- **verify:** Pixel diff q3dm1 byte-identical expected. Also bench a shader-heavy scene (q3dm7 or a map with lots of transparent surfaces) — that's where both the gain and any stale-state bug will show (wrong blending is visually obvious).

### 6. glide-paramindex-gate (glide3x)
- **files:** /home/voidsstr/development/retro-3dfx/toolchain-3dfx/prefix/drive_c/3dfx/H5/GLIDE3/SRC/DISTATE.C (~2527-2530), GGLIDE.C (_grUpdateParamIndex ~4125, _grRebuildDataList ~5104)
- **change:** Stop calling _grUpdateParamIndex()/_grRebuildDataList() (~550 lines of recompute) on EVERY validate. Introduce a dedicated dirty bit set only by state that actually changes the vertex parameter layout (vertex-layout params, tex enables/combine units routing, fog mode, W/Z source) and gate the call at DISTATE.C:2527 on that bit. Alpha blend/test, depth func, chromakey etc. no longer trigger a tsuDataList rebuild.
- **expected:** 2-6% FPS, multiplicative with glide-state-dedup (dedup kills redundant sets; this kills the rebuild for real-but-layout-neutral changes)  |  **risk:** Medium-high — the mask of layout-affecting state must be complete. Missing one producer means the FIFO packet-3 layout no longer matches what the TSU was programmed for: on the Voodoo5 this corrupts BOTH VSA-100s' input identically (SLI broadcast), so it renders garbage rather than half-garbage — easy to spot, at least. Enumerate every writer of paramIndex inputs in GGLIDE.C before choosing the mask.
- **verify:** Pixel diff byte-identical expected. Test matrix must include a texture-enable toggle mid-frame (Q3 2D HUD after 3D world does this) and fog on/off — the two most likely missed producers.

### 7. icd-color4ub-lut (3dfxogl)
- **files:** /home/voidsstr/development/retro-3dfx/toolchain-3dfx/prefix/drive_c/3dfx/SWLIBS/OPENGL/GLIDE3X/GLCORE/S_VARRAY.C (CopyColor4ub ~202-209), S_LIGHT.C (__glClampAndScaleColorf 42-61)

- **verify:** Pixel diff byte-identical expected (LUT values are bit-identical to the fmul result if built with the same single multiply per entry). Any vertex-color tinting difference (view weapon glow, light flashes) fails the commit.

### 8. icd-vertex-dedup (3dfxogl)
- **files:** /home/voidsstr/development/retro-3dfx/toolchain-3dfx/prefix/drive_c/3dfx/SWLIBS/OPENGL/GLIDE3X/GLCORE/S_VARRAY.C (CompileElementsIndexed 1112-1124, __glDrawVertexes_Triangles 2634-2700, batch loop ~3155), INCLUDE/VCACHE.H
- **change:** THE big one. CompileElementsIndexed calls compileElements once per index with count=1 — a vertex referenced by N triangles is copied, color-converted, transformed (__glXForm3, ~35-40 cycles), 1/w-divided and clip-checked N times; Q3 world meshes average 3-6 references per vertex. Fix: within each 36-index batch, dedupe indices (36-entry direct-map on index low bits, or linear scan — batch is tiny) so each unique vertex is compiled exactly once and triangles reference cache slots. Also restructure so the per-index call overhead (setup recompute, updateInverse check) is paid once per batch, not per index.
- **expected:** 10-25% FPS — removes 2-5x redundant transform+clip+fdiv work on the dominant Q3 path; the biggest single win available  |  **risk:** High — core T&L path rewrite. Validation-bit caching in __glValidateVertex3/calcTexture assumes per-copy state; shared vertices must carry correct per-vertex validation flags across the triangles that reference them. Keep the change strictly inside the batch (no cross-batch cache) to bound complexity. FPU-CW note: fewer fdivs executed but same values computed — numerically identical output expected.
- **verify:** Pixel diff q3dm1 MUST be byte-identical (same math, executed once instead of N times). Run full timedemo + a curved-surface-heavy map (patch meshes stress index reuse). Any missing/flickering triangles = cache-slot aliasing bug.
