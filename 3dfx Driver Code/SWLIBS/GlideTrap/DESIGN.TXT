1.    Hash Table Architecture

A hash table using the CRC-32 algorithm for signatures was used to ensure
that textures/frame buffers were saved out only once. The signature is
used to located a candidate "token" that speeds up the search for a match.
This token is used to do a full compare of the texture/frame on disk to
ensure that a full match is made.  If there is a collision, the application
handles it by incrementing the extension of the texture/frame file.

A maximum of 999 collisions in 32-bit CRC hash values are allowed.

2.    Dynamic Arrays

A dynamic array was used for storing states for playback in
grGlideSetstate so that access to a save state is instantaneous.
