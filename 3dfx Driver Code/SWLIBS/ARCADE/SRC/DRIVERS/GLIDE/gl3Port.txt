to run (almost) correctly on Glide3/Voodoo2, but there are
a few undefined/unspecified behaviours and a couple of bugs maybe.
You might find that some of these bugs lack details and could have
gone under more investigations from my part, but Xmas break being

- general question about the grGet( *, param ) function.
In some cases, we know that the call will never return
more than one value:
FxU32 pending_buffers;
grGet( GR_PENDING_BUFFERSWAPS , &pending_buffers ) 
But in other cases, we can't anticipate for sure:
grGet( GR_FB_REVISION, fb_revision)
so, for sure, one should never declare fb_revision as
FxU32 fb_revision but
should one declare fb_revision as
FxU32 fb_revision[2] or FxU32 fb_revision[3] ?
The idea is that one should never assume that there can not
be more than 1 value returned, but there's no upper limit
(3 is in theory the max but no such board exists).

- what about grGet( GR_TMU_MEMORY, &tmu_mem)? 
Can tmu_mem be an array? Does the call return the amount of tmu_mem
per TMU? (it should be, since one could have tmu0=2Mb and tm1=4Mb, right?)
