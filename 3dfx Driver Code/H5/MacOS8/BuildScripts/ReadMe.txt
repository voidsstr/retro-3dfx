AUTOMATED BUILD - 3DFXInstallation & Configuration :------------------------------     First of all, you need to have some applications installed and setup before you run the Automated Build. You can find those applications inside the folder "Extern Apps:" (which is inside the "Automated Build" folder on Pikachu). Here is a list of them and some useful informations :Note : There is a directory structure to respect for all the development tools:								--|	: DevTools:								      --> CodeWarrior Pro 5:									     --> MPW:									     --> SDKs:									     --> AppleScripts:									     --> MiscTools:									      																I - MPW Shell version 3.5     The last version is recommended; since I didn't do much tests on earlier versions, I don't know  if everything will work as fine. To figure out what version is installed on your computer, you can use the mpw command 'version'.If you have never installed MPW on your hard disk before, here is what you need to do :							- unstuff the archive "MPW-GM.sit"							- Drag the MPW-GM folder in the DevTools folderIf you have previously installed an earlier version of MPW, here is what you need to do :							- unstuff the archive "MPW-GM.sit"							- launch the MPW Shell already installed on your system							- execute the following commands from the Worksheet window									 if not `exists -d "{MPW}"busyFolder`									   newfolder "{MPW}"busyFolder				       end						    Directory "insert pathname of MPW-GM folder here"						    Backup -r -a -c -from ":MPW:" -to "{MPW}" -busy "{MPW}"busyFolder						    Backup -r -a -c -from ":Interfaces&Libraries:" -to "{CIncludes}::"(To execute, remember to press the Enter key, not Return, after selecting these command lines in the Worksheet.)							 - execute all the Duplicate commands generated by selecting them, 								  then pressing the Enter key.							 - quit the MPW Shell thatÕs running(The old MPW Shell is located in the ÒbusyFolderÓ inside the MPW folder and can be deleted at your convenience.)II - Metrowerks Code Warrior     You must have Metrowerks Code Warrior installed in your computer. Check Out the scripts from Starteam	Now that you have all the needed applications installed. You need the AB scripts. You can find them in the starteam tree in the devel:h5:MacOS8:BuildScripts: folder.Check out the complete folder. You can use the command "Directory" in the Worksheet window or the menu Directory|Set Directory... .     The SetupAssistant will ask you some questions in order to generate thefile "ab¥startup" and copy it to the "MPW:Startup Items:" folder. Here are some little explanations about the directories you will have to choose :     *** YOU NEED TO HAVE NO SPACES FOR THOSE THREE PATHS ***								* Select the WorkDisk folder ...The WorkDisk directory is where all the source code will be pulled. As each build occurs the directory is wiped. The structure of the directory will be totally dependent on the source pulled.								* Select the Kits folder ...The Kit File Directory is where will be duplicate the Self Extracting Archiveof the installer of  the built target. This directory contains seven directories ('Sunday', 'Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday','Saturday'). Each of these directories will contain kit files that were builtfrom source code on that day of the week.								* Select the Components folder ...The Build Components Directory is where will be all the files created by thisbuild but without installer. Like the Kits directory, this directory containsseven directories ('Sunday', 'Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday', 'Saturday'). Each of these directories will contain kit files that were built from source code on that day of the week.Note : As the setup tells you, the MPW Shell needs to be restarted to use theab¥startup file.Launch an Automated Build-------------------------     To start an Automated Build, you need to start your MPW Shell and set thedirectory to the Buildscripts folder (or start the MPW Shell by double clickingon the ABLunch.mpw file) and then execute the ABLunch.mpw script (synopsis : ABLunch.mpw target-version) or you can execute this commands in the Worksheet window :						Directory "BuildscriptsPath:"	        # set the dir to buildscripts dir	ABLunch.mpw <targetversion>           # to build the specified target     When the build is finished (or a problem occured), you will receive a mailtelling you if the build was successfull or not. Two files will be attached with this mail : FinalReport (all the output of the Worksheet window) and CompilerInfo (all the Warning&Errors messages of each compilations).      You will find in the "Kits" directory (inside the day of the built folder)the installer of the version you just built (a Self Extracting Archive named "<targetversion>.sea") and if the build didn't succeed a folder named : <targetversion>.FAILED is created containing all the files created buy the AB.The "Components" directory works the same way as the "Kits", expect that it contains one more folder (named <targetversion>_<DD-MM-YYYY>.<HHMM>) where youcan find all the reports created during the build).<TARGETVERSION>---------------	If you want to make a special targetversion, you have to fill some files that the AB needs.Each targetversion requires 5 files and all those files need to be inside the "BuildScripts:delivrable_specs:".Here is an explanation of the purpose of each files :( note that each name of those files are built the same way : "<prefixe>_<targetversion>.ab" )	- The PullDown file :  (pd_<targetversion>.ab)			This file contains the path of all the directories to check out, from the starteam tree, required for the targetversion build. 		[one path per line, nothing else]				ex: from pd_voodoo3_beta.ab					"/3dfx/devel/h5/cinit/		/3dfx/devel/h5/glide/		/3dfx/devel/h5/glide3/"		- The CodeWarrior file : (cw_<targetversion>.ab)			This file contains the projects which need to be build for the targetversion build. You need 3 informations per line : project name, target to build and output name.		note that each information needs to be surrounded by '¶"' (option-d + double quote)		[¶"<projectname>¶" ¶"<targetname>¶" ¶"<Outputname>¶"]				ex: from cw_voodoo3_beta.ab				"¶"hrdw_res_mgr.prj¶" ¶"release¶" ¶"3dfx Hardware Resource Mgr¶"		¶"H3_2D_ACCELERATION.PRJ¶" ¶"INIT (release)¶" ¶"3dfx Graphics Accelerator¶"		¶"3DFXGLIDELIB2X.PRJ¶" ¶"release¶" ¶"3dfx GlideLib2.x¶""					- The MakeROM file : (mr_<targetversion>.ab)			This file contains the informations about the ROM that need to be build for this targetversion. You need 3 informations per line : name of the GDX output file, name of the OpenFirmware file, prefixe of the ROM name.		The final name of the ROM will be make by the AB : <prefixe_of_the_ROM>-dd-mm-yyyy.rom (with dd-mm-yyyy the current date)		note that each information needs to be surrounded by '¶"' (option-d + double quote) and the name of the OpenFirmware needs to be a relative path starting from GDX folder.		[¶"<GDXOutput_name>¶" ¶"::<of_name>¶" ¶"<ROMprefixe>¶"]						ex: from mr_voodoo3_beta.ab				"¶"Voodoo3Driver_3000¶" ¶"::OpenFirmware:3Dfx-V3-3000.of¶" ¶"V3-166¶"		¶"Voodoo3Driver_2000¶" ¶"::OpenFirmware:3Dfx-V3.of¶" ¶"V3-143¶""					- The Gather All file : (ga_<targetversion>.ab)			This file contains the informations about all the files that need to be copied into the "Components:<today>:<targetversion>" folder.		You need to have the name of the source file and (if there is) the folder inside which it should be duplicated. You can also add 2 more parameters per line : X and Y coordonnates for the new file into the destination folder.		note that each information needs to be surrounded by '¶"' (option-d + double quote)		[¶"<Sourcefilename>¶" ¶"<DestinationFolder>¶" [¶"<Xpos>¶" ¶"<YPos>¶"]]				ex: from ga_voodoo3_beta.ab				"¶"MacOSGlide Notes¶" ¶"Release Notes¶"		¶"3dfx GlideLib2.x¶" ¶"-->into Extensions Folder¶"		¶"Voodoo3 Read Me¶" """					- The Make Installer file : (mi_<targetversion>.ab)			This file contains the informations about all the files that need to be copied into the SelfExtractingArchive Driver Installer into "Kits:<today>:<targetversion>.sea"		The content is similar to the Gather All file.				ex: from mi_voodoo3_beta.ab				"¶"3dfx Hardware Resource Mgr¶" ¶"parts¶" ¶"80¶" ¶"100¶"		¶"FlashROMVoodoo3¶" ¶"FlashROM¶" ¶"48¶" ¶"48¶"		¶"Software License Agreement¶" ¶"¶" ¶"144¶" ¶"220¶"                    		¶"Voodoo3 Read Me¶" ¶"¶" ¶"144¶" ¶"48¶""			Cron Automated Build--------------------There is a way to execute some builds automatically.
