;
;                               TIMING NOTES
;
;       ========================================================================
;       ========================================================================
;
;       TIMING PARAMETER DEFINITIONS:
;
;       There are currently 11 timing parameters that are passed to the driver
;       that detail information for setting modes at a particular resolution
;       and refresh rate.
;
;       Parameter 1 - Horizontal Total
;       Parameter 2 - Horizontal Sync Start
;       Parameter 3 - Horizontal Sync End
;       Parameter 4 - Vertical Total
;       Parameter 5 - Vertical Sync Start
;       Parameter 6 - Vertical Sync End
;       Parameter 7 - Flags for CRTC
;       Parameter 8 - Pixel Clock
;       Parameter 9 - Refresh Rate
;       Parameter 10 - Character Width
;       Parameter 11 - Checksum
;
;       These parameters are part of a string separated by commas, and are
;       placed into the  \TIMINGS\Xres\Yres\Hz\Default  string value field.
;
;       FOR EXAMPLE;
;       "800,656,752,525,490,492,12,25175000,5994,8,12246"
;
;       The first nine parameters can be easily obtained by cutting and
;       pasting the VBE 3 Refresh Rate field from the bottom left corner of
;       the Timing Standards Spreadsheet once the desired page has been
;       located. The Character Width parameter is most always set to 8, and
;       the checksum calculation is for the reduction of user tampering.
;
;       The Flags for the CRTC operation in parameter 7 are defined as follows:
;
;               Bit 0 = Double Scan Enable
;               Bit 1 = Interlace Enable
;               Bit 2 = Horizontal Sync Polarity ( 0 = Positive, 1 = Negative )
;               Bit 3 = Vertical Sync Polarity ( 0 = Positive, 1 = Negative )
;
;       ALTERNATE TIMING DEFINITIONS:
;
;       An OEM or device may require a special timing for a driver that cannot
;       be defined by using the 11 parameter list that is described above. To
;       accomodate this, we have added support for a more detailed timing list.
;       The driver automatically detects which type of parameter list you are
;       providing, the 11 parameter definition list, or the 22 parameter list
;       described below. ( It counts the number of commas )
;
;       Parameter 1 - Horizontal Total
;       Parameter 2 - Horizontal Display Enable End
;       Parameter 3 - Horizontal Blank Start
;       Parameter 4 - Horizontal Blank End
;       Parameter 5 - Horizontal Sync Start
;       Parameter 6 - Horizontal Sync End
;       Parameter 7 - Vertical Total
;       Parameter 8 - Overflow
;       Parameter 9 - Max Line Scan
;       Parameter 10 - Vertical Sync Start
;       Parameter 11 - Vertical Sync End
;       Parameter 12 - Vertical Display Enable End
;       Parameter 13 - Vertical Blank Start
;       Parameter 14 - Vertical Blank End
;       Parameter 15 - Horizontal Extensions
;       Parameter 16 - Vertical Extensions
;       Parameter 17 - Misc Output
;       Parameter 18 - Sequencer Dot Clock
;       Parameter 19 - PllCtrl0 ( LSB )
;       Parameter 20 - PllCtrl0 ( MSB )
;       Parameter 21 - DacMode
;       Parameter 22 - CheckSum
;
;       NOTE: For convenience, the parameters may be expressed in regular
;       decimal or hexadecimal in the following format;
;
;       FOR EXAMPLE;
;       "0xa3,0x4f,0x60,0x8c,0x68,0x1c,0x20,0xb3,0x60,0x70,0x01,0xdf,0x67,0x88,0x20,0x00,0xcf,0x21,0x29,0x6b,0x00,120"
;
;       For Non-Scaling Digital Flat Panels, place these 22 parameter timing
;       lists into the  \TIMINGS\Xres\Yres\Hz\AltDFP  string value field.
;
;       ------------------------------------------------------------------------
;
;       CAPABILITY PARAMETER DEFINITIONS:
;
;       The  \TIMINGS\Xres\Yres\Hz\Supported  string value designates which
;       capabilities are supported for the resolution and refresh rate, as
;       well as the bit depths that are supported by this mode.  The individual
;       support fields are separated by commas, and can be in any order.
;       All resolutions higher than or equal to 640 by 480 are assumed to be
;       normal Windows Desktop capable modes.
;
;
;       "BPP+8+16+24+32" - This mode supports 8, 16, 24, and 32 bits per pixel.
;       The "+" is a separator, like a comma. There must be at least one bit
;       depth specified.
;
;       "DDRAW" - This mode is Direct Draw capable and will be enumerated in
;       Direct Draw mode lists.
;
;       "TVO_DESK" - This mode is TV OUT capable and will be enumerated in
;       Windows Desktop mode lists when TV OUT is activated.
;
;       "TVO_DD" - This mode is TV OUT capable and will be enumerated in
;       Direct Draw mode lists when TV OUT is activated.
;
;       "NTSC" - This mode is enabled under TV OUT if the TV OUT device is
;       detected as NTSC.
;
;       "PAL" - This mode is enabled under TV OUT if the TV OUT device is
;       detected as PAL.
;
;       "DFP_DESK" - This mode is DFP capable and will be enumerated in Windows
;       Desktop mode lists when a Digital Flat Panel is attached.
;
;       "DFP_DD" - This mode is DFP capable and will be enumerated in Direct
;       Draw mode lists when when a Digital Flat Panel is attached..
;
;       ------------------------------------------------------------------------
;       To force the use of GTF timings on ALL modes, set the  TIMINGS\UseGTF
;       string value to "1".  This overrides any individual settings and uses
;       GTF for all timing calculations.
;
;       To force the use of GTF timings on any individual mode, replace the
;       current string with "GTF" in the  \TIMINGS\Xres\Yres\Hz\Default  string
;       value field.  There are a few exceptions to this operation and that is
;       when the Character Width is not 8 ( usually 9 ), and when the mode CRTC
;       flag specifies DOUBLE SCANNED...  To accomplish these special GTF modes,
;       place the string "GTF" into each of the UNUSED parameter fields, and
;       the correct integer value into the CharWidth or CRTCflags field.
;
;       FOR EXAMPLE;
;       "GTF, GTF, GTF, GTF, GTF, GTF, CRTCflags, GTF, GTF, CharWidth"
;
;       ------------------------------------------------------------------------
;       To define the Optimal Refresh Rate limit to values other than highest
;       possible, change the  \TIMINGS\OptimalRefreshLimit  string value to
;       the desired limit or set the string value to "MAX_EDID"...  The MAX_EDID
;       setting tells the driver to search the monitor EDID for the highest
;       setting specifically listed and limits the "Optimal" refresh to that
;       value...  Now there are some resolutions that are not mentioned in the
;       EDID at all so the  \TIMINGS\OptimalNonEDIDLimit  string value should
;       be set to a reasonable default value such as 85 to prevent problems.
;       ------------------------------------------------------------------------
;       ------------------------------------------------------------------------
;       Add the following line to the [Prev.DelReg] section so previous
;       installions will be removed !!!

HKR,TIMINGS

;
;       ------------------------------------------------------------------------
;                               MODE GENERATION NOTES
;       ------------------------------------------------------------------------

;       1. Select mode widths that are evenly divisible by eight. Failure to
;          do so will cause secondary displays to go blank in multi monitor
;          setups in Win98 and possible problems in Win2k/NT4.
;
;       2. Use the RateTest application from the WHQL DCT test manager after
;          making changes to the TIMINGS key areas. This will help find
;          potential problem before they get to Test.
;
;       3. WHQL requires that every mode on the desktop be supported by DDraw
;          and the reverse.  They also say that if a mode is primarily for DVD
;          playback, then it can be supported by DDraw only.  In Win98, this is
;          possible by removing the mode from the MODES section of the INF but
;          listing it in the TIMINGS section.  Example: 720x480 is done this way
;          in the INF.  For Win2K there is no way with the DMT code to create a
;          mode that shows up in the DirectDraw list and not the desktop.  Also,
;          modes that are less that 640 in the width or 480 in height will never
;          be a desktop mode in both Win98 and Win2k.
;
;       4. To get a new checksum, all you have to do is put the 10 parameters
;          from a mode in Bill Millford's VESA standards document and write the
;          word 'check' for the checksum.  Then after a reboot, the 'check' will
;          be replaced with a valid checksum.
;
;       ------------------------------------------------------------------------
;                               CREATING A NEW MODE - TWO EXAMPLES
;       ------------------------------------------------------------------------
;
;       Let's say you've been asked to create a new mode 640x480 @ 80Hz.  Here
;       are the steps:
;       A. First modify the registry MODES section to add the new mode. To add
;          640x480@80 Hz, you would add ",80" to the middle of the default
;          string in Win98 for  MODES\8\640,480.  It would now look like this:
;          (Default)    "60,72,75,80,85,100,120,140,160"
;       B. Next you would need to add a new registry key called
;          TIMINGS\640,480\80Hz.
;       C. Then you would get the last line from the 640x480@80 sheet in Bill
;          Milford's Excel document and set that string to the '(Default)' for
;          the 80Hz key.  (unfortunately he doesn't have this mode in his
;          document, but it would look something like this):
;          (Default)    "836,670,736,503,481,484,12,33800000,7500,8"
;       D. Then add ",check" to the end of the default string.
;          (Default)    "836,670,736,503,481,484,12,33800000,7500,8,check"
;       E. Copy or add the Supported value in the 80Hz key.  Use the values in
;          the CAPABILITY PARAMETER DEFINITIONS section to modify/add support
;          for various mode specifics.  It will probably look like this:
;          Supported    "BPP+8+16+32,DDRAW"
;       G. Reboot the machine and read the checksum from the registry if not
;          doing GTF.  This value will replace the "check" you wrote in step D.
;       H. Enter all the new registry information into the INF.
;
;
;       Now let's say you've been asked to add a GTF mode timing 800x600 @ 180Hz
;       A. First add another line to the INF in the MODES section to add the
;          new mode. To add 800x600 @ 180Hz, you would add ",180" to the end of
;          the default string in Win98 for  MODES\8\800,600.  The INF would now
;          look like this:
;          HKR,"MODES\8\800,600",,,"60,72,75,85,100,120,140,160,180"
;       B. Next you would need to add a new registry key called
;          TIMINGS\800,600\180Hz to the INF.  The INF would add this line:
;          HKR,"TIMINGS\800,600\160Hz",,,"GTF"
;       E. Copy or add the Supported value in the 180Hz key.  Use the values
;          in the CAPABILITY PARAMETER DEFINITIONS section to modify/add support
;          for various mode specifics.  It will probably look like this in the
;          INF:
;          HKR,"TIMINGS\800,600\180Hz",Supported,,"BPP+8+16+32,DDRAW"
;
;       ------------------------------------------------------------------------
;                               RETAIL MODE DETAIL BEGINS
;       ------------------------------------------------------------------------
;
;
